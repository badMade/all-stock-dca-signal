## Scope
Addressed a high-severity bug in `near_close_dca.py` where boolean instances could silently bypass numeric type validation and be summed as `1` or `0` integers.

## AI usage
Self-directed exploration, planning, and test-driven remediation using automated tooling.

## Assumptions & validation
I assumed `isinstance(value, (int, float))` was the primary source of the boolean trap based on the agent's memory. I wrote a parameterised test (`test_bool_trap_in_validation_functions`) validating that `True` and `False` bypass numeric addition, applied a localized patch, and verified the fix across the test suite and demo execution.

## Design rationale
To maintain code stability and minimize diff size, I added the `and not isinstance(..., bool)` exclusion directly alongside existing `isinstance(..., (int, float))` scalar validators rather than refactoring multiple modules into a novel helper class.

## Testing
Tested explicitly against the boolean edge-case bypassing numeric validation inside `_unrepresented_prior_candidate_part`. Verified via `pytest` and `run_dca.py --demo`.

## Risk & rollback
Low risk. Fails closed when an unexpected boolean scalar is parsed, rather than corrupting risk totals. Rollback is a simple revert.

## Tech debt
Deferred fixes for `json.loads` duplicate key parsing and `math.isfinite` OverflowError handling, focusing this PR strictly on the most critical state corruption risk.
