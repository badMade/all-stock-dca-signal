**Recommendation: do not bring any file from liquidslr/system-design-notes into all-stock-dca.** Use link-only plus own-words rules. Ship the already-approved 41-rule `docs/production-readiness.md` (v0.2). Add a short provenance note that links the upstream repo at commit `9d83887`. Point CLAUDE.md and AGENTS.md at the rules by plain path. Add one shared audit skill. Have the existing `claude-code-review.yml` workflow run that skill as advisory comments only. **Key reason:** the upstream repo has no license, and its 392 PNGs are screenshots of a copyrighted book. Any submodule, subtree, or vendored copy reproduces or redistributes content you have no permission to use. Agents also follow a short distilled checklist better than a 29-chapter corpus. **Main risk:** the rules doc drifts away from the code, or an agent never opens it, because a path reference is a request and not a guarantee. The skill fixes this by forcing a read when it runs, and a small invariant test keeps the doc in shape. **One verification step:** run the new skill against the 2026-10-26 incident (25 unattributed backup buys) and confirm it raises the incident's known open items, duplicate-buy risk and empty executor-id misattribution, as IDEM and RECON findings. If it misses them, the rules need work before anything else. This is not legal advice.

## No license plus book screenshots rules out every copy-based option

**Fact.** With no license, "the default copyright laws apply" and the owner keeps all rights. GitHub's terms let other users only "view and fork" a public repo inside GitHub ([GitHub Docs: Licensing a repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)). Viewing or forking "does not imply that you are permitted to use, modify, or share" the work ([choosealicense.com](https://choosealicense.com/no-permission/)). GitHub also puts the burden on whoever posts content they "did not create or own" ([GitHub Terms of Service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)). The PNGs are copies of the book's diagrams, which are protected expression. A condensed retelling of a book can count as an infringing "abridgment, condensation" ([17 U.S.C. §101](https://www.law.cornell.edu/uscode/text/17/101); [Penguin Random House v. Colting summary](https://www.copyright.gov/fair-use/summaries/penguinrandomhouse-colting-sdny2017.pdf)). The patterns themselves are not protected. Idempotency keys, reconciliation, and token buckets are methods, and copyright does not cover any "procedure, process, system, method of operation" ([17 U.S.C. §102](https://www.law.cornell.edu/uscode/text/17/102); [Baker v. Selden](https://supreme.justia.com/cases/federal/us/101/99/)).

**Inference.** The agent-vault precedent does not carry over. `agent-vault/UPSTREAM.md` works because an MIT license grants copying. Here even liquidslr cannot license the publisher's diagrams. Rules written in your own words, organized by your own rule IDs, with chapters cited only as references, use the ideas and not the expression. That is the lowest-risk path in a public or private repo.

## Your own toolchain makes the submodule path worse, not just neutral

**Fact.** Recursive submodule clones have caused real code-execution bugs. CVE-2024-32002 affects case-insensitive filesystems and is fixed from Git 2.39.4 up ([OSV](https://api.osv.dev/v1/vulns/CVE-2024-32002)). CVE-2025-48384 is on CISA's exploited list and is fixed from 2.43.7 up ([BleepingComputer](https://www.bleepingcomputer.com/news/security/cisa-warns-of-actively-exploited-git-code-execution-flaw/amp/)). The Linux VM runs Git 2.34.1, which is below both fixed versions. The Mac's Git version is unknown. A pinned commit can also disappear after an upstream force-push, which breaks checkouts with "reference is not a tree" ([DeployHQ](https://www.deployhq.com/blog/using-submodules-in-deploy.md)).

**Inference.** A Mac on its default case-insensitive volume meets the CVE-2024-32002 precondition. Link-only avoids the question entirely. Nothing executes, and nothing needs `submodules: true` in CI. If the upstream repo vanishes, the rules still stand, because the link exists only to cite sources. A badMade fork as a backup is permitted by GitHub's terms, but it adds a hosted copy and is not needed.

## Agents follow a short map plus on-demand rules, not a corpus

**Fact.** Anthropic advises keeping CLAUDE.md under 200 lines. It notes that `@` imports "don't reduce its context cost" and that a CLAUDE.md which only says in words "read AGENTS.md" is unreliable ([Claude Code: memory](https://code.claude.com/docs/en/memory)). Reference material and "audit" workflows belong in skills, which load only when invoked ([Extend Claude Code](https://code.claude.com/docs/en/features-overview); [skills](https://code.claude.com/docs/en/skills)). Codex has no import syntax. It stops adding instruction files at 32 KiB by default, and it reads skills from `.agents/skills/` ([Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [Codex skills](https://learn.chatgpt.com/docs/build-skills)). Studies show accuracy drops as context grows ([Chroma: Context Rot](https://www.trychroma.com/research/context-rot)), and context files raise cost by over 20% for little gain ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988v1)). OpenAI found that a ~100-line AGENTS.md used as "the table of contents," backed by a `docs/` system of record, beat one big file ([OpenAI: Harness engineering](https://openai.com/index/harness-engineering/)). When CLAUDE.md and AGENTS.md both exist, Claude Code reads CLAUDE.md only ([memory](https://code.claude.com/docs/en/memory)).

**Inference.** CLAUDE.md (280 lines) and AGENTS.md (223 lines) are already over guidance. Importing the 41 rules would make that worse. Reference the rules by path in both files, and let the skill do the forced read. The AGENTS.md rules that matter (such as draft PRs) reach Claude today only because CLAUDE.md repeats them. Adding `@AGENTS.md` should wait until both files are trimmed. It is a separate change.

## The 10-26 duplicate-buy incident is the first audit target

**Fact.** On 2026-10-26, a manually started Perplexity backup placed 25 buys when the Claude slot had no payload. A second backup could not attribute them, and two agents misattributed them. Open items are duplicate-buy risk from an early backup and misattribution from empty executor-ids.

**Inference.** This is the Payment System and Hotel Reservation problem: one logical purchase must map to one idempotency key across *every* executor, and reconciliation must attribute every in-window order or fail closed. Scope the audit to `scripts/idempotency.py` (are ref_ids derived the same way by Claude and backup executors?), `scheduler_lease.py` and `dca_runner` Gate 4 (can a manual backup run without the sole-executor lease?), `scripts/broker_reconciliation.py` and Gate 6 (does an empty executor-id fail closed?), and the backup prompts in `claude/dca-executor-prompts/live-mirror/`. Note the 2026-10-22 carve-out: unproven order-history completeness is log-and-continue, but rogue in-window orders still fail closed. Findings are advisory. Each accepted fix becomes its own draft PR with a regression test.

## Conclusion

The upstream repo's value to all-stock-dca was always the patterns, and those were never owned by anyone. The owner already pulled them out when writing the 41 rules. What remains in the upstream repo is the protected part: the screenshots and the book's wording, plus its supply-chain overhead. So the integration question becomes a rules-delivery question: how to get a short standard read at the right moment by two agents with different loading rules. A path reference, a forked audit skill, and an advisory CI pass answer that without adding a single upstream byte.

The deeper payoff is that the rules expose drift between the three entry points. The 10-26 incident shows that one pattern applied to one executor and not another is exactly how real money moves twice. An audit that checks each rule ID against all three entry points tests the repo's biggest structural risk directly.
