Clean run: log a compact summary to the in-app message center with order count, total notional, and ticker list. Include the Gate 6.5 line: every ticker resized or zeroed, with its reason code.
Any abort, skip, or cap breach: alert on ALL THREE channels below, in order, and do not stop after the first one succeeds. State the slot, the failing gate, and the reason in each.
1. IN-APP MESSAGE CENTER, primary (config/notifications.json alert routing).
2. REPO ALERT FILE, durable fallback. If the repo is reachable, write the same text to the path printed by `python3 -c "import dca_paths; print(dca_paths.stream_root('market_open_dca', 'alerts', '<YYYY-MM-DD>-<slot>-<gate>.txt'))"` (resolve it by invoking dca_paths, exactly as the 12:30 prompt does for $ROOT, never a bash `${VAR:-literal}` fallback: dca_paths defaults an unconfigured checkout to a checkout-relative cron_tracking/ tree, so a literal fallback writes the alert where no dca_paths-based consumer such as scripts/alert_digest.py ever looks; from Python, dca_alerts.write_alert_file() does the same -- never a bare repo-relative artifacts/ directory, which .gitignore discards: 23 of the 2026-08 alerts claimed a durable copy under artifacts/alerts/ and every one of them was lost) so the alert survives the session. If the repo is unreachable, skip this step and say so in the primary alert: a Gate 2 failure is exactly the case where this fallback cannot work.
3. EMAIL, belt-and-braces. SEND the same text to the operator email configured for alerts (never hardcode a personal address), with a subject naming the slot, the ET date, and the failing gate so the alert is greppable later. Send it -- do not leave it sitting as a draft. An earlier revision of this line asserted the email connector had no send capability and told you to create a draft instead; that produced ~50 undelivered alert drafts between 2026-08-06 and 2026-08-26, none of which the operator read (see docs/alert_digest.md). If the connector you actually hold genuinely exposes no send capability, OR you attempt the send and it fails (auth, throttling, a provider or network error): create a draft AND record that email delivery did not happen. A failed send is exactly as undelivered as a draft; treating only absent capability as the fallback case leaves a failed send with no record at all. Channels 1 and 2 were written before this step and cannot mention a failure that had not happened yet, so go back to them: post a follow-up note to the message center and, if the repo is reachable, append the same line to the channel-2 alert file, naming the slot, the gate, and why the send failed. A draft is NOT delivery and must never be the only channel used.
Zero candidates: stay silent ONLY when the Gate 5 document shows a genuinely quiet, fully evaluated tape -- provider_error_count: 0 AND manual_review_count: 0 AND both withheld_incomplete_trend_window_tickers and withheld_contradictory_base_tickers empty AND no_data_count short of the whole evaluated universe -- with evaluated_count > 0 REQUIRED before that comparison means anything: when Gate 4's compatible executor already covered every active ticker, --already-covered-tickers empties the scored universe and the document reports evaluated_count: 0 with no_data_count: 0, so a bare equality test fires vacuously and alerts on a healthy fully-served run (Codex review: "Treat a fully covered universe as served"). Read evaluated_count: 0 with a non-empty already_covered_tickers as SERVED -- record the compatible executor's coverage per Gate 4 and stay silent. Only with evaluated_count > 0 does no_data_count == evaluated_count mean the universe fetch failed. An empty buy list is reachable four other ways, and every one of them is a run that found real candidates and could place none of them: a broken per-ticker fetch (reported, not fatal -- the command still exits 0), a truncated trend fetch turning every price-qualified row into a manual_review_candidate, bars that never reach back to the start of the trend window, and a row whose base and prior-low evidence contradict each other. Each of those looks identical to a quiet tape from buy_count alone. This line previously read "Zero candidates: stay silent" without qualification, which flatly contradicted Gate 5's own alerting rule above and, being the later instruction, could suppress exactly the notification that rule exists to raise (Codex review: "Limit Gate 9 silence to healthy zero-candidate runs"). When any of the four is nonzero, alert per the three channels above naming the specific list. Silence is for an evaluated empty result, never for an unevaluated or withheld one.

STANDING PROHIBITIONS
Never place a sell. Never touch options, crypto, or margin. Never retry a failed submit. Never build a buy list without the repo. Never place an order larger than Gate 6.5's buy_usd for that ticker. Never override a gate because the situation looks like an exception. If you find yourself reasoning toward "the safe thing here is to place the order anyway," that is the signal to stop and alert instead.
