CLOUD-CLONE CHECK (cloud container only). It applies when exactly one checkout survives the four probes AND that checkout was found by probe 4 alone, meaning its canonical path is outside /sessions. That is the shape of a scheduled cloud container whose repo was attached as the task's source. For any other surviving checkout (a /sessions mount, or the bridge) skip this paragraph; nothing about those runs changes. Before anything else in the run, including Gate 0, run from that checkout's root, with DCA_CRON_TRACKING_ROOT already exported before Python starts: `python3 -m scripts.cloud_preflight --repo-root . --evidence-remote "$DCA_EVIDENCE_REMOTE" --evidence-root "$DCA_CRON_TRACKING_ROOT" --trading-day <today in America/New_York, YYYY-MM-DD>`. If DCA_EVIDENCE_REMOTE or DCA_CRON_TRACKING_ROOT is unset or empty, do not run it: abort `Failing gate: Gate 2` with "cloud clone environment incomplete: <the variable NAME> is unset" (names only, never values). Give the command at most 180 seconds and do not retry it. Exit 0 with a line starting PREFLIGHT_OK means the checkout is the pinned release and the evidence store was pulled: Gate 2 PASSES, and the 40-character SHA that line prints is this run's code version. Exit 2 means abort `Failing gate: Gate 2` with the GATE2_ABORT reason copied verbatim from its output. Any other exit, a timeout, or no PREFLIGHT_OK line also aborts `Failing gate: Gate 2`, with "cloud preflight did not complete". Keep the literal `Failing gate: Gate 2` in the alert so scripts/alert_digest.py buckets it correctly. A cloud-clone abort STANDS: never fall back to mcp__remote-devices__device_bash or any other checkout to get past it, never pass --init, never set or change DCA_PINNED_SHA, never edit, reset or clean the checkout to make the preflight pass (a modified tracked file or an untracked file is exactly what it refuses), and never trade. Put the abort reason in the alert but never the evidence remote URL (it can embed a credential) and never the account number. The remedy to name is "fix the cloud environment or pin, then re-run the slot manually while its window is open", not "reconnect the folder".
