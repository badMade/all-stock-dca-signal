# Applied: DCA triage digest fixes (2026-10-27)

Record of what the 2026-10-27 triage digest's "fix all of this" pass changed, what it left alone and
why, and how to undo it. Keys are DCA Issues `Key` values so the triage reconciler can match this PR.
No repo code, config, order-placement or cap logic changed. The only live changes are two read-only
reporting task prompts outside the repo. The operator approved those edits in chat on 2026-10-27.

## Applied to live tasks (`~/Claude/Scheduled`, the folder `scripts/check_live_prompt_drift.py` reads)

### `dca-end-of-day-digest`
Group A text (`GROUP-A-PASTE-READY-2026-10-17.md` section 1), made concrete against the repo:

| Key | Before | After |
| --- | --- | --- |
| `false_all_clear` | "Did each slot run" = `lastRunAt` falls on today | Outcome from `verify_schedule --json`: CLEAN only when `verified` AND `order_submit_status` is submitted / not_submitted_no_candidates / not_submitted_budget_exhausted. `market_closed` is acceptable. Any other or unlisted value is named. An unreadable source makes the headline UNVERIFIED, never ALL CLEAR |
| `hardcoded_normal_cap` | "the $180 Normal-tier daily cap" | `budget.budget_tier` / `daily_cap_usd` / `weekly_cap_usd` from the run's own `run_state.json`. `config/budgets.json` is used only to validate the tier name. Prints "tier not recorded" when no tier was recorded |
| `misattribution` | Orders "grouped into slot clusters by created_at" | `verify_schedule --json --orders-json` attribution from each slot's run_state. Unattributed and ambiguous orders are anomalies |
| `output_limit_workaround` | One fetch with no transcription guard | Each page saved raw, then `scripts.assemble_order_pages`. A non-zero exit means INCOMPLETE and no totals |
| `approval_required` (digest side) | Gmail draft fallback when Slack fails | Repo alert file `<cron root>/alerts/<date>-digest-slack-failure.txt`, no Gmail |

The per-order ceiling check also moved from a hard-coded "$10.00" to the run-time value of
`config/budgets.json` `max_per_order_usd` (currently $16) / `whole_share_max_per_order_usd`. The
old figure was stale and flagged nothing between $10 and $16.

Evidence this was live, not hypothetical: `verify_schedule --json` for 2026-10-27 reported
`ok: true` while 10:30, 11:30, 12:30 and 13:30 ended `not_submitted_error` and 14:30 recorded
`no_orders_submitted`, a value not in `config/run_classification.json`. The old digest's
`lastRunAt` rule would have called all seven slots healthy.

### `dca-notion-run-log`
`recorder_transcript_unavailable`: STEP 1 now builds each slot's row from `verify_schedule --json`,
each slot's `run_state.json`, repo alert files and `list_scheduled_tasks`. Session transcripts are
optional detail only. A source that cannot be read gets a `source_unavailable` row, and slots
whose outcome is unknown get "Unverified" rows, so the log is never silently empty. STEP 2 gained
an `order_submit_status` → Status mapping.
