# Plan-first backup executor

Status: proposed (2026-10-06). Phase 1 of a six-phase change; no code is implemented by this
document. Operator approval is required before Phase 2 (tests).

## Context

Claude on the Mac Studio is the primary executor for seven slots (09:35, 10:30, 11:30, 12:30,
13:30, 14:30, 15:30 ET). Perplexity scheduled tasks are delayed backups (09:55, 10:50, 11:50,
12:50, 13:50 and 14:50, 15:45 ET; see `config/scheduled_tasks.json`
`standing_perplexity_backup_policy`). Broker order history is the only evidence of what was
bought.

Today the backup prompts make the LLM do the sizing math in prose. The repo already holds the
tested logic for it, so the prose is a second, unverified implementation that drifts:

- Gate 5 candidates: `scripts/stream_candidates.py` (the `cands` and `planner_candidates` rows),
  using `near_close_dca.raw_ladder_multiplier` and the $1 or $2 base selection.
- Caps, whitelist, priority, one order per ticker: `dca_runner.plan_orders`.
- Idempotency key: `dca-runner-<slot_id>-<trading_day>-<TICKER>` (`docs/live_wiring.md`).

Findings from Phase 0 that shape this decision:

- The repo already designs per-ticker exclusion, so a partly finished Claude batch can be
  completed (`claude/PERPLEXITY-CLAUDE-COORDINATION.md` section 1). The
  `standing_perplexity_backup_policy.mechanism` text still says to stand down on any Claude
  evidence, which contradicts it. The live backup prompts are not in this repo.
- The effective per-order ceiling is $16 (`dca_runner.MAX_PER_ORDER_USD`, derived from the
  ladder; `config/budgets.json` `circuit_breakers.max_per_order_usd`). "$10" survives only in
  stale prose.
- RVI, VCX and TRLV are active in `config/tickers.json` (re-added 2026-08-16). QBUT is the only
  excluded symbol.

## Decision

Introduce a plan file and move backup sizing into code.

1. **Plan file** (`schemas/order_plan.schema.json`, draft below). The primary slot runner writes
   it before placing orders. It lists the slot's intended buys in allocation-priority order.
2. **Mac-first backup.** Each backup run, after its unchanged gates and double evidence poll,
   checks for the Mac Studio with a bounded call (D8: 60 seconds). If reachable and a valid plan
   for this day and slot exists, the backup places only planned orders that the broker history
   shows unplaced. This replaces the 2026-09-23 "never check the Mac" rule.
3. **Mac compute.** Reachable but no valid plan: run the repo planner on the Mac through
   `run_local_subagent`, so real repo code runs and nothing is vendored.
4. **Cloud compute.** Mac offline, not found, timed out, or device call error: run a stdlib-only
   single-file build of the planner (`dist/backup_planner.py`, generated by a script from repo
   code, stamped with source commit and content hash, with a drift test) in the Perplexity
   sandbox on data the agent fetched from Robinhood and dumped to files.
5. **Fail closed.** Planner error or missing inputs: no orders, status `failed_unexpected_error`,
   notify. Any validation failure of a plan file yields an empty plan and a structured error,
   never an exception to the caller and never a partial buy.
6. **Evidence.** The state record carries `plan_source` of `mac_plan`, `mac_compute` or
   `cloud_compute`. Mac files, logs and plans are inputs only, never purchase evidence.
7. **Code re-validates on every path:** universe, do-not-buy list (QBUT), per-order cap, daily and
   weekly caps against a fresh full-day order pull, no duplicate same-day ticker, and a fresh
   quote still below the prior close.

| D4 | Literal. If the plan's total would exceed the remaining daily or weekly cap, or any order exceeds the per-order cap, the backup buys nothing and reports why. No trimming. | `plan_orders` never shrinks or back-fills (`dca_runner.py:2180`) |

### Plan file schema (draft)

The authoritative draft is `schemas/order_plan.schema.json`. Shape:

```json
{
  "schema_version": 1,
  "trading_day": "2026-10-06",
  "slot": "1130",
  "generated_at_et": "2026-10-06T11:30:12-04:00",
  "generator": "claude",
  "ladder_version": "2026-10-04",
  "universe_hash": "<sha256 of sorted active tickers joined by newline, plus trailing newline>",
  "orders": [
    {
      "symbol": "MU",
      "notional_usd": 6.0,
      "multiplier": 3.0,
      "drop_pct": 2.4,
      "decision_price": 100.0,
      "prior_close": 102.46,
      "prior_low": 100.5,
      "ref_id": "dca-runner-1130-2026-10-06-MU"
    }
  ]
}
```

Serialization is canonical (sorted keys, fixed separators, trailing newline, orders in
allocation-priority order) so identical inputs give byte-identical files.

Mapping to existing fields (`scripts/stream_candidates.py:1363`): `notional_usd` from
`desired_usd`, `decision_price` from `current_price`, `prior_low` and `prior_close` unchanged.

### Amendments from implementation (Phases 2 to 4)

- **Sizing source.** Live sizing uses `config/per_ticker_sizing.json` (interpolated, $1 base) for every
  active ticker; `config/sizing_ladder.json` is only the fallback. `ladder_version` is therefore the
  composite `<sizing_ladder version>+<per_ticker_sizing version>` (`dca_order_plan.current_ladder_version`),
  and `drop_pct` may be below 0.1.
- **Slot ids** are `0935`..`1530` with no `ET` suffix, matching `dca_runner.SLOTS` and `ref_id`.
- **Caps are all-or-nothing and written out** in `dca_order_plan._cap_errors` instead of calling
  `plan_orders`, which keeps the orders before a cap boundary and whose multiplier-consistency check is
  bound to the calibration files read at import time. `execute_plan` still runs `plan_orders` at placement.
- **Primary-side emit** is `scripts/emit_order_plan.py`, run as the first step of Gate 7 in each live-mirror
  prompt, because placement in the live prompts is prose and not a code runner. A failed emit writes nothing,
  exits 2, and does NOT block the primary's own placement (only the backup depends on the plan). Live
  scheduled bodies are unchanged until a human repastes the mirrors.
- **Cloud single-file build** is deferred: the import closure of `dca_order_plan` is about 4.3 MB, so it
  needs a separately reviewed extraction of a small shared ladder-core module first.

## Alternatives considered

| Option | Why not |
| --- | --- |
| Keep prose-only prompts | Sizing and cap math stay untested and drift from the repo, which is the problem being solved. |
| New standalone planner | A second implementation of ladder and caps. `plan_orders` and Gate 5 already exist (CLAUDE.md warns duplicated logic drifts silently). |
| Change `gate_sole_executor`'s return shape (SEVEN-SLOT-TRANSITION-PROPOSAL section 3) | Shared, load-bearing, and out of scope. Reconciliation is a new pure function; existing callers are untouched. |
| Repo-derived planner (chosen) | Reuses the tested logic; the only new code is plan I/O, validation and reconciliation. |

## Consequences

- Backup sizing is tested code. The backup depends on the Mac being reachable for the best path
  and degrades to compute paths otherwise.
- `dist/backup_planner.py` is a generated artifact that must be kept in sync; a test fails on
  drift.
- The primary runner gains a write step before placement (Phase 4), a behavior change to a live
  path that needs its own review and acceptance run.
- Plan files never become evidence. Reporting and run classification are unchanged.
- New top-level modules are added to `pyproject.toml` `py-modules` per the repo invariant. The schema file
  is documentation that no code reads at runtime, and the repo ships no other schema in `data-files`, so it
  is deliberately not packaged (corrected after review; an earlier draft of this ADR said otherwise).

### Design gaps found in review (2026-10-07)

Raised by an automated review of PR #1619 and verified against the code and config. None affects the
primary Claude slots. Status after the follow-up change:

1. **Cross-slot top-ups: fixed.** `config/budgets.json` `one_order_per_ticker_per_day` is false, so a later
   slot may buy a ticker again, resized by `scripts/same_day_top_up_gate.py`. A Claude plan already carries
   the resized notional, so `finalize` reconciles it against THIS slot's window only
   (`dca_order_plan.placement_window`, `reconcile(scope="slot")`); a computed plan cannot resize, so it keeps
   the day-wide exclusion. The prompts' rule 5 now reads "one order per ticker per slot".
2. **Compute path is not the Gate 5 signal path: mitigated, not fixed.** `compute_plan` applies the ladder to
   quotes only and skips the stream generator's trend and data-confidence gates, so it can plan a ticker the
   primary rejected. `finalize` therefore returns `SHADOW_ONLY` for any computed plan and places nothing
   (`COMPUTE_PLACEMENT_ENABLED`, off). Rebuilding `compute` on `scripts/stream_candidates.py` is still open
   and is the precondition for turning the switch on.
3. **Buying power: fixed.** `compute` and `finalize` require `--buying-power` and fail closed when it is
   missing, unusable, or below the batch total.
4. **Spread (Gate 6.7): fixed.** `finalize` requires `--fresh-spreads`; a missing, crossed, unusable, or wide
   spread skips that ticker only, using `near_close_dca._quote_bid_ask` validity and
   `StrategyConfig.max_bid_ask_spread_pct`.

### Known limitations

- **15:45 ET backup may run out of time before 16:00 ET** because of the Mac-first check. Accepted
  by the operator on 2026-10-06. No slot-specific timeout or optimization is added.
- D6 is open; idempotency on `ref_id` is not relied on.
- Two engines can still start simultaneously and both see an empty window (accepted risk,
  coordination doc section 1).
- Perplexity cannot read this repo, so the Phase 5 prompts remain a manual paste step.

## Rollback

Every phase is additive. The backup prompts switch back by repasting the previous prompt text
(kept under `claude/dca-executor-prompts/`); the primary emit step (Phase 4) is removed by
reverting its commit, and the plan file is ignored by anything that does not opt in. No existing
`gate_sole_executor` or `plan_orders` caller changes behavior. Shadow mode (Phase 6) runs at
least five trading days with no placement before any live decision.
