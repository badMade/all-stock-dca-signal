## Scope
Optimized pandas iteration in `apply_budget` within `analysis/2026-06-29-revised-ladder/dca_revised_ladder_analysis.py` to significantly improve execution time on large groups by switching from `to_dict('records')` to standard tuple extraction.

## What
Replaced `to_dict(orient="records")` with `itertuples(index=False, name=None)`. Also explicitly extracted relevant column indexes before iteration to retrieve the data efficiently from standard tuples, replacing expensive per-row dictionary creations.

## Why
`to_dict('records')` forces Pandas out of its vectorized backend and instantiates a brand-new Python dictionary object for every single row. In a hot path function iterating over potentially thousands of grouped decisions, this per-row allocation acts as a significant bottleneck for memory and CPU execution time.

## Impact
Measurable execution time improvements. Based on a local test simulating `apply_budget` across a 2,000-period 100-symbol mock dataframe:
- Before (`to_dict('records')`): ~8.05 seconds
- After (`itertuples(index=False, name=None)`): ~5.28 seconds
This represents roughly a 34% speedup in hot path parsing iteration.

## Assumptions & validation
Assumed `idx_name` and required column lookups (`planned_spend`, `close`) maintain stability and can safely be captured once before loop execution instead of per-row. Verified functionality using the established test module `test_dca_revised_ladder_analysis.py` which passes completely.

## Design rationale
Standard tuples accessed by integer indices (`row_tuple[idx_planned]`) bypass the overhead of creating NamedTuples (which `itertuples` defaults to doing if `name=None` is omitted) and fully sidestep Python `dict` constructor overhead, aligning with the `AGENTS.md` guidelines for replacing `iterrows` and `to_dict`.
